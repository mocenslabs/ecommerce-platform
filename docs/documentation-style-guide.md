# Documentation Style Guide

## Language

All documentation must be written in English.

---

## Markdown

Use GitHub Flavored Markdown.

---

## Headings

Every document should begin with:

- Title
- Overview

---

## API Documents

Recommended structure:

- Overview
- Responsibilities
- Endpoints
- Business Rules
- Relationships
- Frontend Integration
- Related Documentation

---

## Architecture Documents

Recommended structure:

- Overview
- Diagram
- Explanation
- Design Decisions

---

## Writing Style

Use concise technical language.

Avoid ambiguous wording.

Use active voice whenever possible.

---

## Diagrams

Prefer ASCII diagrams.

Keep diagrams synchronized with the implementation.

---

## Code Blocks

Always specify the language.

Example:

```python
print("Hello")
```

---

## Versioning

Documentation must evolve together with the codebase.

Every architectural change should update the relevant documentation.
